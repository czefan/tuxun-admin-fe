# 项目检查与修改记录

检查日期：2026-09-28。

## 技术栈与架构结论

Vue 3、TypeScript、Pinia、Naive UI、Vite 和 UnoCSS 适合当前后台，没有必要整体替换。项目已有按业务划分的 API、契约类型、路由权限和列表组合函数；本次保留这些边界，修复公共逻辑和具体业务问题。

- 包管理统一为 pnpm **12.6.0**，本地与 CI 一致；安装使用 HTTPS npmmirror，审计使用 npm 官方源。
- 更新存在安全公告的运行依赖和构建依赖；`pnpm-workspace.yaml` 的 overrides 明确记录传递依赖补丁。
- 移除只适用于 Linux x64 glibc 的直接原生依赖，由上游按平台选择绑定，兼容 CI 的 Alpine 环境。
- 移除老旧 `vite-plugin-svg-icons`，本地图标统一交给已有的 `unplugin-icons` 编译，保留 `SvgIcon` 使用接口。
- 业务列表和分页函数移除使类型校验失效的 `any` 联合返回类型；错误提取放在独立工具中，避免列表依赖路由和登录 store。

## 已修复的问题

| 范围        | 原问题                                                                    | 修改后的行为                                                   |
| ----------- | ------------------------------------------------------------------------- | -------------------------------------------------------------- |
| 多活动筛选  | 数组被编码成 `activity_ids[0]`，后端和 Mock 均无法按契约读取              | 统一发送 `activity_ids=101&activity_ids=102`                   |
| 表格分页    | 删除最后一页记录后停在空页；数组筛选重置共用原始引用                      | 自动回到有效页；使用独立的默认参数副本                         |
| 表格错误    | 优先显示 Axios 内部错误；空响应可能保留旧结果                             | 优先显示后端信息，异常数据明确报错                             |
| 候选列表    | 中途请求失败伪装成数量截断，返回部分数据                                  | 失败抛出，由调用方区分错误与正常截断                           |
| 登录初始化  | `/user/info` 的错误拦截器提前清会话，改变 epoch，导致 store 跳过 403 分类 | 初始化请求交由 store 统一收尾                                  |
| 登录入口    | 仅排除 `prod`，默认 `production` 模式仍可能包含测试登录入口               | 测试登录只在 `test` / `mock` 模式开放                          |
| 登录回跳    | 编码后的反斜杠、控制字符等未过滤；测试登录丢失回跳地址                    | 校验解码路径，并保留合法回跳参数                               |
| 路由权限    | 用户管理仅在页面内部限制 Level 3，菜单和路由未限制                        | 路由声明 Level 3，普通管理员不显示入口                         |
| Mock 登录   | 默认自动登录超级管理员，跳过登录验证；登出可能跳真实 IdP                  | 默认匿名，走模拟授权回调；Mock 登出停留本地                    |
| 官方题目    | 错误地禁止编辑已结束活动的题目，坐标必填未校验                            | 只限制新建；编辑允许，提交检查完整坐标和文本限额               |
| 活动编辑    | 已结束活动仍可修改时间，且每次保存都发送时间字段                          | 锁定结束活动的时间，更新其他字段时不发送时间                   |
| 图片上传    | 压缩仅执行一次，可能仍超限；损坏图片和压缩失败会继续提交                  | 检查解码、按输出大小有限次压缩、失败阻止上传；处理期间禁用提交 |
| 必填图片    | 隐藏已移除的封面后，父表单仍认为图片存在                                  | 活动、奖品、题目同步移除状态，要求重新选择图片                 |
| 通知编辑    | 加载失败仍能发布空表单；预览 Blob 未释放；旧请求可能回填                  | 加载失败禁用发布、重试入口、请求序号保护、卸载释放资源         |
| 内容位      | 三个并发请求共用 loading；切换标签重新加载覆盖草稿                        | 独立加载状态，未成功加载不允许保存，切换保留草稿               |
| 扫码核销    | 关闭窗口后旧查单结果可能重新启动相机；相机不可用无手工入口                | 会话序号保护、释放相机、手工输入核销码、重复请求保护           |
| 地图交互    | 旧搜索/逆地理编码结果可能覆盖新值；清空坐标残留地址和标记                 | 忽略过期回调，清空时同步清理，卸载后不再更新                   |
| 坐标展示    | 经纬度为 0 被误判为无坐标                                                 | 按空值和有限数字判断                                           |
| Mock 热更新 | `includes('/api/')` 错把 `/src/service/api/` 模块当作未实现 API           | 仅匹配 URL 路径的 `/api/` 前缀                                 |
| Mock 一致性 | 通知详情缺少权限检查、投稿作者筛选未生效、活动时间按字符串比较            | 增加权限/筛选，按时间戳比较                                    |
| 工程检查    | `check` 隐式修复代码，CI 只构建不检查                                     | 分离 `lint` / `lint:fix`；CI 与提交前执行完整检查              |
| 部署示例    | Nginx 示例按根路径服务，生产却使用 `/admin/`                              | 对齐子路径、回调路由回退和静态资源缓存                         |

已有的 `contract/api.md` 与 `contract/apifox-import.json` 修改保留；重新生成契约类型，同步其中新增的活动删除接口定义。本轮没有执行任何真实业务数据修改、提交或部署。

## 验证方法

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm test:e2e
pnpm build
pnpm audit:deps
```

Vitest 覆盖请求数组编码、分页越界、异步结果竞争、参数重置、登录错误分类、富文本过滤、回跳地址、压缩失败和扫码生命周期。Playwright 使用真实 Chromium 与 MSW，覆盖主要页面、登录与权限、活动筛选、内容草稿和编辑失败场景。34 个 Vitest 测试、19 个 Playwright 测试均通过；契约、Lint、类型检查与生产构建均通过。另以 Chromium 打开生产预览 `/admin/login`，确认页面正常渲染、无运行异常且不显示测试登录入口。

本轮完整依赖审计从 53 条公告（其中生产依赖 24 条）降至 0 条。审计结果只代表查询时的已知公告，并不等于证明所有运行场景均无缺陷。

## 后续改进与联调范围

1. **真实后端联调**：浏览器业务测试使用 MSW。学校 OAuth 白名单、同域 Cookie 属性、服务端权限/并发核销、真实上传、高德代理与物理摄像头，需要在对应环境验证。
2. **候选项规模**：下拉候选依然有 200 条加载上限。活动/通知增长后应采用服务端搜索和分页，不应无限扩大 `page_size`。
3. **Mock 覆盖**：Mock 仍是轻量内存模拟，并未完整实现全部后端字段校验、事务和媒体存储。需要后端集成测试补充保证。
4. **依赖兼容声明**：`openapi-typescript` 当前声明 TypeScript 5 peer，部分 Devtools 传递包声明旧版 Vite peer。当前 TypeScript 6 / Vite 8 下已验证类型生成、检查、构建和开发页面；这些上游声明仍应在后续升级时复核，未通过配置隐藏警告。
5. **代码拆分**：较大的业务页可按“查询列表 / 编辑弹窗”逐步拆分；权限常量和表单约束也可进一步集中。无需为当前规模引入微前端或额外全局状态框架。
6. **部署**：Nginx 文件是对齐生产 base 的参考配置，真实站点目录与 `/api`、高德代理仍需按部署环境填写；本轮未修改线上服务器。
